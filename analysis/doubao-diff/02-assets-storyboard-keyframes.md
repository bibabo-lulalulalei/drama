# 七、实际行为影响汇总

1. **资产制作更强调复用和群众分层**
   CHR/SCN/PROP/VOICE/STYLE 的原有路由和版本合同不变；CRD 进入同一资产闭环。 recurring 群众必须真实参考，单镜群众不强制产图，无台词群众不强制 VOICE。

2. **本地生图比例处理更可审计**
   精确比例不再假定由 `--ratio` 一次完成；pad/crop、适配后上传和原文件追溯都有明确边界。

3. **H3 使所有视频段必须按 4-15 整数秒重排**
   原版 Seedance 2.5 的 25-30 秒规划不再可用。镜头、SEG、全集、用户锁定时长和轻量唯一视频必须按当前合同闭合。

4. **动作单元反造假能力增强**
   当前版明确禁止预设镜数、统一单镜秒数、先 SHOT 后反填动作单元，并要求逐镜具体删除损失。八镜指标更难以形式化凑数。

5. **用户阅读稿输出会明显改变**
   固定总览、提要、章节、片段和逐镜条目；禁止表格；片段标题可读化；人声改用引号。但内部十五列和导演底稿格式并未同步改成引号。

6. **连续段不再一律宣称 tail 是硬首帧**
   Ref2VA 中 tail 是普通连续事实参考；只有单图 I2VA 才使用 `previous_tail_as_start_frame + frame_position:first`。真实 tail 仍是 continuous 的硬性前置条件。

7. **视频 Prompt 变成有血缘的双层编译**
   中文底稿承载完整导演事实，英文 H3 成稿只转换语言、结构和标签，不得改剧情、镜头、原台词、素材职责或时长；只有英文成稿实际提交。

8. **关键帧创作算法基本未变，群众可验收性增强**
   3-4 张、K0-K5、image_edit、SCN 必传、300-500 字、十法和完整模式逐张确认均保留；新增 CRD 真实传图和群众逐人/分区调度。

9. **dry-run 与真实任务被明确区分**
   recurring 群众可校验到请求槽位和实际 bytes 哈希，但 dry-run 不能被写成已提交、已生成或已验收的视频证据。

# 八、风险、残留与真正缺失判断

## 8.1 当前资产确认文案未完全纳入群众

- 当前 `storyboard.md` 439 行明确 Ref2VA 不声称 API 强制首帧。
- 当前 692、694 行仍把 tail FRM 称为“0 秒首帧视觉基准”。

**判断：术语风险，不是直接算法冲突。**
合理解释应为“0 秒连续事实的视觉基准”，不是 I2VA 的硬首帧模式。若执行者只读后文，可能误把 Ref2VA tail 再标成 `previous_tail_as_start_frame`。

- 当前 `storyboard.md` 48 行仍有该措辞。
- 当前 25、184 行明确唯一 H3。

**判断：低优先级一致性问题。**
实际时长和模型硬门应以后者及 `tools/h3.json` 为准，不能借旧措辞切换模型或突破 4-15 整数秒。

**判断：职责独立新增，不是遗漏。**

## 8.5 原版独有或当前替换项清单

真正属于原版独有、当前不再适用的主要是：

- 三份 Ref 顶部的集中摘要；多数为去重，不构成算法丢失。
