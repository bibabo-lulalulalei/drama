# 群众外观、参考资产与连续性

涉及路人、宾客、学生、卫兵、观众等背景人物时，规划、剧本、资产、分镜、关键帧和视频阶段读取本文件。本文件统一维护群众分层与机器字段；其他 Reference 继承这些规则，不另建群众合同。

## 外观要求

所有背景群众都必须描述样貌，包括只出现一镜、没有台词或独立剧情功能的人群。描述粒度按景别、清晰度和复现需求确定：

- 远处模糊人群：人数或密度、年龄与体型分布、发型轮廓、服装款式与配色、显著群体特征、画面区域、行动和反应。无法分辨的脸不逐人编造细节。
- 可辨认成员：逐人登记稳定成员标识、可见外观和位置锚点；同镜及后续镜头继承。无台词也不能省略外观。
- 同一群体在多个镜头或 SEG 复现：保留群体与成员标识，复用已验收的群众参考图，在相关关键帧和视频请求中真实传入。只登记路径或写“参考该图”不算传入。
- 有独立台词、重要特写或承担关键因果行动的人：按角色职责升级 CHR，继承此前成员的可见外观和状态，保留 `member_id` 到 `character_id` 的对应；不能在升级时换一张无关的脸。

是否建立视觉资产按稳定复现需求决定；是否建立 VOICE 按是否承担可辨识人声决定。无台词群众不要求独立音色。低声议论等不可辨识话语可按环境声设计；清晰口号或群体对白仍须登记声音主体和逐句台词。

## 数据与文件

完整模式在 `project_data_card.json.crowds[]` 登记当前剧情需要的群众。分镜使用 `storyboard_ep_N.json.segments[].crowds` 和 `shots[].crowd_ids` 绑定；视频 `segments[].crowds` 保存实际执行快照，没有群众时明确写 `[]`，缺少该字段即不符合当前格式。

需要独立参考资产的群体登记 `category: crowd`、`asset_id: CRDxxx`，沿用资产版本、状态和来源规则。单镜群体也使用 `crowd_id: CRDxxx` 追踪，但群体标识本身不意味着必须生成一份图片资产。已有人群图先验收、登记并复用；只补当前集必要参考，不预制未来集。

每组群众的执行字段如下；完整数据卡可先记录剧本已确定的初始信息，实际镜头和参考文件在对应阶段补齐，视频生成前必须完整：

```json
{
  "crowd_id": "CRD001",
  "state_id": "STATE001",
  "continuity_scope": "recurring",
  "visibility": "identifiable",
  "count_or_density": "约二十名婚宴宾客",
  "appearance": {
    "age_range": "约二十五至六十岁",
    "build": "体型有胖瘦差异，中等身材为主",
    "hair": "黑色或灰色短发、盘发为主",
    "wardrobe": "现代正装；M01穿深蓝西装与白衬衫，M02穿米色外套",
    "palette": "深蓝、炭灰和米色为主",
    "distinctive_features": "正式婚宴装束，未戴统一徽章"
  },
  "members": [
    {
      "member_id": "CRD001-M01",
      "appearance": "灰发短寸、方脸、体型偏瘦的中年男子",
      "screen_position": "主通道左侧前排"
    },
    {
      "member_id": "CRD001-M02",
      "appearance": "黑色齐耳短发、圆脸、中等身材的女子",
      "screen_position": "主通道右侧前排"
    }
  ],
  "screen_position": "分坐主通道两侧，保持主角轮廓清楚",
  "action": "主角举杯时前排两人先转头，其余宾客随后停止交谈",
  "allowed_changes": "按分镜改变视线和坐姿；不无因更换成员、发型或服装",
  "reference_source_id": "CRD001_v01"
}
```

- `continuity_scope` 为 `shot|recurring`：只在一个镜头内出现使用 shot；同一批群众在多个镜头或 SEG 复现使用 recurring。`visibility` 为 `indistinct|identifiable`；identifiable 必须提供非空 members。`count_or_density` 必须服从用户锁定的人数或密度，不静默把准确人数改为近似。
- `appearance` 的六项都是非空文字。用于底稿逐字核验的 `appearance` 与 `members[].appearance` 属于内部事实锚点，沿用 `director_draft_language: Chinese`；专名保留原文，用户可见预览按 `output_language` 表达同一事实。`members` 可在远处模糊人群中为空；成员的 `member_id/appearance/screen_position` 均非空，可附 `character_id: CHRxxx` 表示已升级的角色。组内成员标识唯一且可追溯。
- `screen_position/action/allowed_changes` 均为非空文字，逐镜实际走位、手位和视线写入十五列分镜现有栏目，不增加第十六列。对关键角色与可辨认成员逐人调度，对模糊人群按整体区域、朝向和反应调度。
- 同一 `crowd_id + state_id` 下，人数或密度、appearance 和成员外观保持一致；位置、动作与视线可按分镜变化。剧情确需变装、伤妆、成员组成变化或时间跳跃时，建立新 `state_id`，填写非空 `change_reason`，回写完整模式数据卡的状态记录，保留人物身份继承关系，并准备需要的新参考版本。不得仅改 Prompt 继续引用不符的新旧状态。
- `reference_source_id` 在单镜、无独立参考时可以为空。recurring 必须绑定真实图片来源，来源可为已批准 CRD 资产版本或已验收的用户来源 `SRCxxx`。完整模式资产阶段完成前允许待补，视频执行快照中不允许待补。

## 生成与复用

群体参考图应清楚呈现服装、组成、关键成员的可见身份，以及需要保持的位置关系；根据用途选择群像或可清楚指认成员的设定板，无需机械给每个远景群众生成三视图。带入已有群众、人物和风格参考时用 image_edit，身份与风格采用边界明确。参考图生成后按资产规则验收、展示和批准，再登记真实文件、Prompt 与版本。

视频 `reference_inputs` 中使用 `role: crowd_reference`，其 `source_id` 与群众 `reference_source_id` 一致，填写真实 file、order、adopt、exclude。资产来源必须 approved；用户来源必须能追溯到来源登记与验收。引用的图片必须与实际 CLI `--image` 上传文件一致。多个群体可共用一张已验收且成员可辨认的参考图，不伪造额外输入槽位。

recurring 群众的 SEG 必须填写 `request_snapshot_file`：调用前可指向保存为 UTF-8 的 `tools/workflow_video.py submit --dry-run` 输出 JSON，执行后指向实际返回的 task_file。两者现有 `slots` 字段均保存图片槽位、文件路径和实际 bytes 的 sha256；校验将 `order` 对应到 `ref_image_{order-1}`，核对图片未漏传、文件一致且哈希未失效。dry-run 只证明准备的请求，不得冒充已经提交或生成；实际执行后继续核对真实工具任务记录。其他 SEG 可选填写该字段，填写时同样检查。

群众图、角色三视图和高光 KF 是普通参考。仅图片参考可用 `image_to_video + Ref2VA`；有音视频时用 `media_to_video + Ref2VA`。不得为通过帧模式把群众图或设定板标成实际 first/last frame。确实已经是目标构图和剧情时刻的实际画面，才按首尾帧专属职责登记；不能临时改写群众参考的职责。

群众中文外观描述和成员锚点完整进入导演编译底稿，H3 成稿将这些事实译成英文，保留原语言台词、歌词与可见文字。交给 h3-prompt-writing 时同时提供当前执行快照、实际媒体槽位及采用/剥离范围。底稿、成稿和真实图片出现冲突时回到最早失效的合同修正，不由成稿自行换人或改变服装。

## 轻量模式

轻量模式同样描述全部群众外观：在规划预览中确认可见外观与素材方向，扩充到内部十五列分镜，再编译 Prompt，并保存视频 manifest 的群众执行快照。只用这些现有文件，不创建项目数据卡、分镜 JSON 或独立群众资产审批包。

需要复用同一群体时可以使用已经验收、当前任务可用的用户图片。若需要新增群体参考资产、逐阶段审批或存在人物、群众或场景连续性风险，返回规划切换完整模式并重新确认；不得在已获授权的轻量视频之外追加图片或音色生成。

## 验收与变更

单镜内和跨镜头都检查人数与组成、脸部可见特征、体型、发型、服装、随身物品和位置变化，区分正常遮挡/进出画与换脸、复制人物或无因消失。文字和参考图用于降低漂移，实际画面仍需人工查看；发现问题按现有返修和生成授权规则处理，不自动追加重生。

群众外观、成员或参考图变更时，递增对应数据与资产版本，只使实际依赖旧事实的分镜、KF、Prompt 和视频失效。升级为独立角色时保留原群体成员的来源映射。校验只检查声明字段、ID、稳定快照、已登记文件、批准引用、请求快照的图片槽位与哈希，以及中文底稿覆盖；英文翻译是否正确及画面是否漂移由人工核验，不能用 lint 通过代替看图。
